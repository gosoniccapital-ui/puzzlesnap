Sprint 6.1 • Living Spec & Architecture Decisions

CunFashion Admin Security & Passcode Auth Gate

Dự án: CunFashion Web Full Stack (cunfashion.com) • Quyền sở hữu: Đại Ka

Bảo Toàn Trạng Thái Tuyệt Đối: Hệ thống đã được kiểm thử với 16/16 Unit Tests PASS 100%, Next.js 15.5.25 Build hoàn thành với Exit Code 0, và không có bất kỳ rò rỉ secret nào trên Git.

1. Unspecified & Implicit Decisions

  • Web Crypto API Standard (crypto.subtle): Thay vì dùng module crypto độc quyền của Node.js, toàn bộ token HMAC-SHA256 được xây dựng trên chuẩn W3C Web Crypto. Quyết định này giúp code chạy mượt mà $100\%$ trên Next.js Edge Middleware mà không bao giờ gặp lỗi thiếu polyfill trên Vercel Edge.
  • Cấu trúc Token Compact: Token được lưu dạng base64url(payload).base64url(signature) không cần thư viện bên thứ 3 (như jsonwebtoken hay jose), giữ bundle size của Middleware chỉ 34.8 kB.
  • Timing-Safe Comparison: Cả việc so khớp Passcode và xác thực chữ ký HMAC đều sử dụng thuật toán so sánh constant-time (bitwise XOR), ngăn chặn triệt để kỹ thuật tấn công đo thời gian (Timing Attack).
  • Suspense Boundary cho Login Page: Bọc form login trong <Suspense> để tuân thủ quy tắc App Router của Next.js khi sử dụng hook useSearchParams(), bảo đảm trang render tĩnh tối ưu.

2. Deviations from Initial Specification

  • Không có sai lệch: Mọi yêu cầu của Đại Ka (Biến môi trường bảo mật, giao diện login CunFashion, API login/logout, Middleware chặn /admin và API mutations, nút Logout trên dashboard) đều được tuân thủ chính xác $100\%$.

3. Considered Trade-offs

  • In-Memory Rate Limiting vs. Redis/Upstash: Ở quy mô hiện tại của Sprint 6.1, việc dùng in-memory sliding window Map cho serverless instance là phương án tối giản (Simplicity First), không làm phát sinh chi phí hạ tầng bên ngoài. Nếu sau này cần phân tán đa vùng, có thể nâng cấp lên KV/Redis mà không thay đổi interface API.
  • Session Cookie vs. JWT Bearer Header: Chọn Cookie HttpOnly, Secure, SameSite=Strict giúp bảo vệ người dùng khỏi tấn công XSS đánh cắp token và tấn công CSRF, đồng thời trình duyệt tự động gửi cookie trong các request quản trị.

4. Maintenance Notes

  • Mật khẩu quản trị mặc định: Được khai báo an toàn trong .env.local với biến ADMIN_MASTER_PASSWORD.
  • Khi deploy lên Vercel Production: Chỉ cần thêm 2 biến ADMIN_MASTER_PASSWORD và ADMIN_SESSION_SECRET vào Vercel Environment Variables.
  • File kiểm thử: tests/admin-auth.test.mjs có thể chạy định kỳ bằng node --test tests/admin-auth.test.mjs.
